# 十一步流程細節

專案資料夾的標準結構（每一步的產出都存檔，方便回頭修改與交接）：

```
<專案>/
  00_資料/              使用者給的 PDF、講義、純文字（或 00_輸入_*.txt）
  01_事實清單.md        宣傳類：事實逐條＋來源頁碼＋衝突＋敏感資訊
  01_內容分析.md        教學類：觀念、比喻、迷思、衝突→解答骨架、縮短取捨
  02_三種創意概念.md    3 個概念：英文提示詞＋中文對照＋比較表
  03_分鏡文本.md        每場景：畫面／旁白／大字卡／秒數＋事實核對
  04_概念試看/          3 支 10 秒動態試看
  05_聲音試聽/          同一句話的三種聲音
  06_完整版/            成片
  video/                Remotion 專案（engine/template 複製而來）
```

## ① 輸入
- 問：專案資料夾路徑、想做什麼（一句話）、資料在哪。沒有資料就改用問的。
- 使用者的舊資料在別的資料夾時，**複製**一份進 `00_資料/`，不要直接引用路徑（日後追溯來源）。

## ② 理解素材
**宣傳類 → 事實清單**：分「學什麼／設備／榮耀／升學出路」等類別，每條標頁碼。
**教學類 → 內容分析**：
- 核心觀念（通常 1–3 個）與原文定義
- 原文自帶的比喻（＝現成的畫面）與縮短時的取捨
- 迷思與檢查題
- **戲劇骨架**：衝突①→解答①→衝突②→解答②→伏筆（這是所有概念共用的敘事骨架）
- 目標長度換算字數：旁白語速 +18% 約 5 字／秒；宣傳片旁白只佔總長一半左右

**一定要列出**：
- 資料衝突（例：PDF 寫錄取率 50%、使用者更正 34% → 採用者更正；「全國賽包辦」實為分區賽）
- 敏感資訊（教師姓名、教室、手機、Email）→ 預設不放
- 對目標觀眾太難的術語（例：國中生不懂「技優甄審」）→ 換說法或不放

## ③ 定調問答
見 `question-bank.md`。三輪：目的 → 調性 → 細節。每題附「(推薦)」選項。

## ④ 創意概念
見 `concept-design.md`。**一律 3 個**，彼此要在「世界觀、構圖、鏡頭、剪接、配樂」五個層級都不同。

## ⑤ 文本
- 表格：`# | 段落 | 畫面（標註視覺化方式） | 大字卡 | 旁白 | 約秒數`
- 附「事實核對」表：影片每個說法 → 事實清單編號
- 列「刻意不放」的內容與理由
- 多個概念同時製作時：旁白共用、一張表對照三種畫面（`03b_三概念分鏡.md`）
- 自己檢查用詞精確：「26 人次」不是「26 人」；「10 位國手」不能畫成「10 個國家」

## ⑥ 動態試看（10 秒）
- 每個概念寫**全新**的 Remotion 元件（參考 `concepts/` 的寫法），10 秒內演完內容的核心轉折
- 每支有自己的曲風配樂、對準畫面事件的音效、1–3 句旁白／角色聲
- 抽 6 格檢查後再交付；常見問題：場景太小、標題蓋住主體、對話泡泡不消失、結尾沒演完

## ⑦ 細節
- 聲音：同一句代表性台詞，用 YunJhe（男）、HsiaoChen（女）、HsiaoYu（女）各合成一次給使用者聽
- 語速：教學 +18%、招生 +15%、現場公告 +3%
- 角色劇（小劇場類）可用多個聲音：旁白＋角色 A＋角色 B

## ⑧ 製作
1. 旁白逐句合成（edge-tts，內容 hash 快取）→ 量出每句實際秒數
2. 時間軸：場景長度 = max(旁白＋前導＋尾巴, 視覺需要) → 補足到該概念曲速的整數小節 → 調整總長逼近目標
3. 配樂：概念指定曲風；章節交界放 impact＋riser；旁白期間音樂壓到 35%（或 duck 0.16）
4. 事件音效：解鎖／答對／蓋章／翻車……每個畫面事件一個音效
5. Remotion 元件讀時間軸（timing.json 或 spec.json），每個場景用 Sequence
6. 算圖 1080p30、CRF 18、AAC 192k

## ⑨ 品檢（不過不交）
見 `production.md` 的品檢清單。兩層都要過：
1. **技術品檢**（`qa.py`）：重疊、出界、唸錯、黑畫面、響度
2. **概念忠實度**（人工，必做）：拿出原始提示詞／範本 README 的「概念忠實度檢查」表，逐項用**連續格**驗證招牌特徵還在。
   通用化、加速、省事的寫法最容易悄悄拿掉招牌特徵（例：手稿的筆變成亂飄、線稿變成 emoji），總覽圖單格看不出來。

## ⑩ 交付與沉澱
- 成片命名：`<用途>_<概念>.mp4`；響度 −14 LUFS
- 使用者滿意的概念 → 提示詞存進 `references/prompts/NN_<名稱>.md`、場景程式存進 `concepts/<名稱>/`
- 發現的新坑 → 補進 `lessons-learned.md`

## ⑪ 最終品檢（成片的最後一道關卡，不過不交）

⑨ 是製作過程中的品檢（版面、回聽、概念忠實度）；⑪ 是**對最後要交出去的那一支 mp4** 再量一次。
理由：重新算圖、合併、響度處理都可能帶進新問題（字型沒載完造成字幕抖動、換頁空一格、接縫黑畫面），
⑨ 量的是上一版，不能代表成片。

**一律跑**（任何範本、任何流程做的影片都適用；不會修改任何檔案）：
```
python final_qa/final_qa.py out/<成片>.mp4 --lufs -14     --spec src/data/spec.json --layout qa_layout.json     --terms <旁白裡的英數詞,逗號分隔> --text <旁白全文.txt>
```
輸出 `final_qa.html`（報告＋截圖總覽）與 `final_qa.md`（摘要），**兩個都要交給使用者**。
`--spec`、`--layout` 有就給：加上後會多量字幕＝旁白、字幕同步、Netflix 字幕規範（G1～G6）與版面。

| 代號 | 檢查 | 門檻／依據 |
|---|---|---|
| F1 | 字幕閃爍（字幕帶前後有字、中間空 1～2 格） | 0 |
| F2 | 字幕抖動（同一頁字幕外框逐格變動，常見原因：字型分片沒載完） | 0 |
| F3 | 黑畫面 | 無 >0.3 秒 |
| F4 | 最長靜止 | 參考值 |
| F5 | 規格 | 1920×1080、30fps、H.264、AAC |
| F6 | 響度／真峰值 | 目標 ±1 LU、≤ −1 dBTP（EBU R128 量測） |
| F7 | 中段無聲 | 無 >1.5 秒 |
| F8 | 長度 | 依專案 |
| F9 | 英數詞唸法（時長比對） | 每個詞都要「＝某個正確唸法」；「TTS 自己猜」的要明定 |
| F10 | 多音詞（重送、轉圈、便宜…） | 人工試聽，清單附正確讀音 |

**字幕規格**（給 `--spec` 時自動量，G1～G6）：依 Netflix 繁體中文字幕規範——每行 ≤16 字（必要時 18）、
每秒 ≤9 字、每頁 5/6～7 秒、行尾不放標點；字幕串起來要等於旁白原文；每頁字幕要落在所屬旁白句的時間內。

**版面規格**（Remotion 專案，用 qa_layout.mjs＋QaProbe）：安全區左右 80px、上下 100px（Remotion 官方
video-layout 規則）、文字不重疊、圖塊不重疊、文字間距 ≥12px、字級 ≥24px、對比 ≥4.5:1（大字 3:1，WCAG AA）、
不闖進字幕區、標題 ≤2 行、不孤字換行、內容置中。

**再加一步人工＋AI 看圖**：逐節看截圖總覽（主標題是否明顯、是否擁擠、字級階層、重點是否一眼可辨）。

**品檢規則有改動時**：先跑自我測試（故意做壞的影片每一種都要被抓到），確認品檢本身沒壞
（範本E：`engine/qa/selftest.py`）。

全部通過才進入交付；有問題就修正、重算、從 ⑪ 重跑。
