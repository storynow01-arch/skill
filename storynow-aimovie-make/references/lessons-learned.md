# 實戰教訓（每一條都是真的發生過）

| # | 發生什麼 | 以後怎麼做 |
|---|---|---|
| 1 | 提示詞寫「56 屆全國賽金銀銅包辦」，資料其實是**分區賽**包辦、全國賽銅牌 | 照資料，影片寫「分區賽包辦＋全國賽銅牌」，並告訴使用者差異 |
| 2 | 錄取率 PDF 寫破 50%，使用者更正為約 34% | 使用者更正優先；所有版本（Python、Remotion、範本）同步改 |
| 3 | 做了 10 種「風格」，使用者說三種「動態效果差不多」 | 換皮≠不同概念；概念要在世界觀、構圖、鏡頭、剪接層不同 |
| 4 | 1-1 闖關版沿用舊產線分鏡，使用者指出不是從內容產生 | 教學稿一律從純文字重新分析、重新產生概念 |
| 5 | 使用者回答「1 和 4」，但題目只有 3 個選項 | 下一輪用一題確認，不要猜 |
| 6 | 研習影片差點放主任手機號碼 | 會轉傳的影片，手機、私人 Email 預設不放，先問 |
| 7 | 「26 人次」寫成「26 人通過」；「10 位國手」差點畫成「10 個國旗」 | 文本自檢用詞精確度與視覺暗示 |
| 8 | 字幕長句擠成兩行 | build.py 自動分頁（24 字） |
| 9 | 試看片結尾標題還沒寫完就結束 | 動畫在結束前 0.5 秒完成並停留 |
| 10 | 兩個算圖同時跑，各自慢到 3 倍以上 | 一次只跑一個；批次用腳本依序跑 |
| 11 | 像素字型太寬，時間欄斷行 | 像素字型的小欄位縮字、加 nowrap |
| 12 | 長時間背景工作後，回覆滑成英文 | 一律繁體中文 |
| 13 | 合成波風格的夕陽在標題後面干擾閱讀 | 文字多的場景，背景主體要避開文字區 |
| 14 | 等角場景只佔畫面一角 | 試看前先算世界範圍，讓主體佔畫面 70% 以上 |
| 15 | 旁白回聽全部變亂碼 | faster-whisper 吃 numpy 陣列時必須是 16 kHz；48 kHz 要先 resample_poly(x, 1, 3) |
| 16 | 「故意做壞」的長標題沒被抓到 | 它自動換行、沒有超出畫面——品檢要用真正會壞的案例驗證，並同時做反向測試 |
| 17 | Node 腳本放在 skill 資料夾找不到 @remotion 套件 | 執行前把 .mjs 複製進專案資料夾再跑 |
| 18 | 照片場景標題的 \n 沒換行 | 文字容器要加 whiteSpace: pre-line |
| 19 | 版面品檢在某一格卡死兩個多小時 | 量測探針等字型載入時沒有逾時 → 探針 2.5 秒保底、renderStill 45 秒逾時、qa.py 子程序 30 分鐘逾時 |
| 20 | 旁白回聽把「192.168」「0 到 255」判成唸錯 | whisper 寫阿拉伯數字、稿子是國字 → 比對前兩邊都拿掉數字；數字唸法由唸法規則保證 |
| 21 | 標亮的「門牌」被判成和整句重疊 | 有上下層（祖先／子孫）關係的兩段文字不算重疊 |
| 22 | 手稿範本的補充說明被字幕膠帶蓋住 | 區塊內容的基線不要低於 y=840（品檢「闖進字幕區」有抓到） |
| 23 | 快剪範本的巨大數字頂到上方副標 | 數字字級上限 520；重疊比例低於門檻時品檢抓不到，仍要看總覽圖 |
| 24 | 手稿範本通用化後，筆變成「照公式飄在空中」、線稿換成 emoji；品檢全過，使用者一看就說「效果差很多」 | 範本 README 列招牌特徵清單，交付前用連續格逐項核對；筆一律走 `penkit`（筆尖＝正在畫的那一筆），圖示一律走 `sketches` 線稿 |
| 25 | 同一次檢查發現闖關範本沒有「走地圖」、XP 只是時間條、圖示是彩色 emoji；快剪範本沒有「字變成東西」、圖示是彩色 emoji | 招生片的招牌特徵是寫在「為那支片客製」的場景裡，通用化時要逐條搬進通用渲染器；圖示一律走 `sketches` 線稿＋各範本的畫法（PixelIcon／penkit／NeonIcon） |
| 26 | 範本流程要手動跑 7 個指令、還要從測試專案複製 tpl，容易漏 | `make_video.py --template X` 一行做完，並自動同步 skill 最新範本程式 |
| 27 | 範本D「小測驗」字壓到吊牌框與圓孔，版面品檢全過；第一版「字超出所屬圖形」只比外框範圍，負面測試還是抓不到 | 容器圖形標 `data-qa-box`、框裡的字標 `data-qa-in`；探針沿框線取樣，點落在字的範圍內就算；新檢查一定要拿真的壞例子跑一次 |
| 28 | 17 字含句號的旁白被切出只剩「。」的字幕頁，清掉標點後變成 0.17 秒的空白頁 | 字幕字數一律不算標點（`cap_len`）；只剩標點的頁併回上一頁；沒有標點可切時用 jieba 切在詞的交界 |
| 29 | 很短的句子（「還不行。」）字幕只停 0.5 秒，低於 Netflix 的 5/6 秒 | 後面有空檔就延長；緊接下一頁就跟相鄰頁合併（合起來 ≤16 字） |
| 30 | loudnorm 設 TP=-1，AAC 編碼後峰值浮到 −0.7 dBTP | 一律 TP=-1.5 |
| 31 | build 用 whisper 對齊時，faster-whisper 連 Hugging Face 檢查模型，連線斷在 CloseWait 就整個卡住（log 沒有任何訊息） | 模型已下載就設 `HF_HUB_OFFLINE=1`；長流程用 `PYTHONUNBUFFERED=1` 才看得到卡在哪 |
| 32 | AI 耳朵兩次聽同一個音檔，第一次說「轉圈」對、第二次說聲調錯；「切成」因清單誤查成 qiè 被誤報 | AI 耳朵只當提醒，標出的要人工聽；誤報就補進 `final_qa/多音字清單.json` |

| 33 | 長句字幕「塞滿 16 字才切」，切出「電機與電｜子群」「影視動畫廣告｜班」「1000 到｜5000 元」這種拆詞、只剩 1～3 字的尾巴頁（2026-10-08 屏榮招生片） | build.py `split_caption` 改成在 ≤16 字前提下找最好的切點：標點 > 連接詞前 > 英數交界 > 詞的交界（先轉簡體再 jieba 斷詞），兩邊盡量等長；數字範圍與「數字＋單位」不拆；不留 ≤3 字的頁。Netflix 的 16 字、5/6 秒、9 字／秒照舊強制 |
