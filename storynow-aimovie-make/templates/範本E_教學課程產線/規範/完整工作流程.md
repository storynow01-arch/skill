## ② 寫文稿與分鏡 ✅

- **雙軌稿** `01_腳本\<單元>-<節>_<標題>.md`：每個場景 `VISUAL:`（畫面）＋ `NARRATION:`（旁白，一行一句）
- **分鏡** `01_腳本\<單元>-<節>_plan.json`：場景型別（12 種）＋畫面文字＋每個物件的 `cue`（旁白唸到哪句時出現）
- **寫作規則**（這兩天的教訓，全部寫進規範）：
  | 規則 | 例子 |
  |---|---|
  | 文稿寫**專業寫法**，唸法交給程式 | 寫 `mail.google.com`、`99.9%`、`1960 年代`，不寫「mail 點 google 點 com」「百分之九十九點九」 |
  | 物件文字用**旁白裡的說法** | 旁白說「Wi-Fi 看影片會卡」，膠囊就寫「Wi-Fi 看影片會卡」，不另寫一套 |

  | 產品名照官方商標 | NGINX、YouTube、macOS、Wi-Fi |
  | 中英文之間空一格 | 「用 Wi-Fi 看影片」 |
  | 畫面文字不用「，」「——」 | 建置時自動轉：「，」→ 空白、「——」→ 空白、「 — 」→「：」 |

## ④ 唸法清單＋逐字審稿（AI） ✅

1. **唸法清單**（程式）：
   ```powershell
   py 04_引擎\qa\read_check.py 11_品檢\文稿總審 1-1 1-2 …
   ```
   逐節列出每個英數詞、數字、多音詞、符號，以及「實際送給 TTS 的文字」。
   多音詞讀音：先用 OpenCC 轉簡體再查 pypinyin（詞組庫是簡體，繁體詞查不到會讀錯），`多音字清單.json` 的「詞」優先
2. **逐字審稿**（Claude 讀每一句）：檢查清單
   - 錯別字、漏字、贅字
   - 技術內容正確（數字、年份、協定、產品行為）
   - 用詞前後一致、專業寫法、台灣用語
   - 句子長度：字幕每頁 ≤16 字、≤9 字/秒，太長的句子拆開
   - 容易聽錯的說法（同音詞、連續專有名詞、數字串）
   - 物件文字與旁白一致
3. 產出 `11_品檢\文稿總審_<單元>\審稿報告.html／.md`：每一處「原文 → 建議 → 理由」

## ⑦ 選聲音 ⛔ ✅

**選定後**：寫進 `00_規範\配音設定.json`（克隆聲音或設計聲音的 `voice_id`＋`style`），之後整門課都用同一組。

```powershell

```

## ⑧ 配音（Gemini Flash TTS／edge-tts） ✅

**配音選擇規則（2026-10-06）**：專案自己的 `.env.local` 有 `GEMINI_API_KEY` 才用 Gemini Flash TTS（自動最新正式版），沒有就用 edge-tts。`tts_gemini.py` 沒找到這個專案的金鑰會自動改跑 `tts.py`（edge-tts，輸出格式相同）；只看專案根目錄的 `.env.local`，不讀系統環境變數、不借別的專案的金鑰。

```powershell
py 04_引擎\tts_gemini.py 01_腳本\1-1_通訊協定與封包.md
```
- 模型 `auto`：每次查 Google，自動用**最新正式版 Flash TTS**（目前 gemini-3.8-flash-tts）
- 相鄰場景併成約 700 字一段送出（省請求數），用 faster-whisper 逐字時間＋difflib 對齊已知文稿，切回每場 mp3＋句級字幕
- 數字、IP、縮寫照 `發音規範.json` 轉；edge-tts 專用的權宜寫法（多音詞同音字、ping→聘）在 `skip_rules` 跳過
- 配額用完（429）會停，重跑同一指令從快取接續；短時間限制會自動等
- **整節成功才覆寫 `02_語音`**：先寫 `_staging`，全部完成＋對齊檢查通過才搬；原檔移到 `_上一版`；對齊可疑句 >10% 就停（聽過沒問題加 `--accept`）
- edge 權宜寫法（多音詞同音字、ping→聘、mail／GET／gov 逐字母、單獨 com→c o m、Mega→Megah）在 `skip_rules`，送 Gemini 時原文照送
- 沒有金鑰時自動用 `tts.py`（edge-tts），輸出格式相同
- **配音前：唸法標準題** `py 04_引擎\qa\pron_test.py`（30 題：數字、網址、IP、縮寫；沒全過就不配音，每日批次開跑前自動跑）
- **壞音檔關卡**（2026-10-06，2-8／2-14 實際遇到 Gemini 回傳後半段整段無聲）：任一場每秒不到 2 字（30 字以上）或場內空白超過 6 秒（有「……」測驗思考停頓的場放寬到 12 秒）→ 那一段快取移到 `_gemini_cache\_壞掉的段落_<日期>`、不覆寫、exit 5，重跑同一指令會重新要那一段
- **配完音先估整集長度** `py 04_引擎\qa\ep_estimate.py EP3=2-1,…`（封面片頭 14.6 秒＋各節＋片尾測驗，跟實際成片誤差 0）
- **額度**：付費 Tier 1 每天 100 次請求，**台灣時間 15:00 重置**；`11_品檢\run_v8_daily.sh` 每天 15:05 自動接續（額度用完寫 `.quota_stop` 停，隔天接著做）。
  ⚠ 這類長時間程序開在 Claude 桌面 App 底下，App 重啟會被一起關掉（10/6 實際發生）→ 每天 15:05 後看 `v8_batch.log` 有「每日接續 <今天> 開始」

## ⑫ 渲染 → 合併 ✅

```powershell
powershell -File render_v2.ps1 -Ver v8 -Ids 1-1,1-2,…      # 每節檢查 exit code 與檔案時間
py 04_引擎\assemble.py EP1 1-1 … 1-7 --ver v8             # 封面＋片頭＋過渡＋各節，響度 −16 LUFS
```
- **有一節失敗就停，不合併**（批次腳本已加）
- **整集長度上限**（2026-10-06）：每集壓在 30 分左右、最長 30.5 分。超過就在合併時處理，**不重渲、不重配**：
  `py 04_引擎\assemble.py EP3 2-1 … --ver v8 --fit-minutes 30.5`（或寫進 `00_規範\集長度設定.json` 的「套用的集」，批次自動套用）——
  句間超過 0.7 秒的停頓縮到 0.45 秒（測驗時段、每節開頭 1.5 秒、換場前後 0.4 秒不縮），再整體等比加速（atempo 不變調），05_輸出_節 原檔不動
- 渲染期間不要同時跑大量 API 請求（10/5 實測會搶網路，字型下載失敗）
