## ① 建立課程專案 ✅

```powershell
py <範本E>\engine\new_course.py D:\課程\新課程
```
- 建出固定資料夾：`00_規範`、`01_腳本`、`02_語音`、`03_素材\brand`、`04_引擎`、`05_輸出_節`、`06_輸出_集`、`11_品檢`
- 自動建 `.env.local`（填 `GEMINI_API_KEY`）與 `.gitignore`（金鑰、語音快取不進 git）
- 需自備：`03_素材\brand\` 的 `cover.jpg`（封面）、`intro.mp4`（片頭）、`logo.png`（LOGO）

## ② 寫文稿與分鏡 ✅

- **雙軌稿** `01_腳本\<單元>-<節>_<標題>.md`：每個場景 `VISUAL:`（畫面）＋ `NARRATION:`（旁白，一行一句）
- **分鏡** `01_腳本\<單元>-<節>_plan.json`：場景型別（12 種）＋畫面文字＋每個物件的 `cue`（旁白唸到哪句時出現）
- **寫作規則**（這兩天的教訓，全部寫進規範）：
  | 規則 | 例子 |
  |---|---|
  | 文稿寫**專業寫法**，唸法交給程式 | 寫 `mail.google.com`、`99.9%`、`1960 年代`，不寫「mail 點 google 點 com」「百分之九十九點九」 |
  | 物件文字用**旁白裡的說法** | 旁白說「Wi-Fi 看影片會卡」，膠囊就寫「Wi-Fi 看影片會卡」，不另寫一套 |
  | 台灣正式用語 | 虛擬機器、服務等級協定（SLA）、網域名稱、連接埠 |
  | 產品名照官方商標 | NGINX、YouTube、macOS、Wi-Fi |
  | 中英文之間空一格 | 「用 Wi-Fi 看影片」 |
  | 畫面文字不用「，」「——」 | 建置時自動轉：「，」→ 空白、「——」→ 空白、「 — 」→「：」 |

## ③ 第⓪關：文稿檢查（程式） ✅

```powershell
py 04_引擎\qa\term_check.py          # 預設檢查 01_腳本 全部文稿與分鏡
```
- 規則：`00_規範\用詞規範.json`（可自己加）
- 檢查：網址寫成唸法、字母拆開寫、年份／百分比／編號用中文、協定名稱小寫、SLA 譯名、集數寫法、
  大陸用語（樂詞網對照，含誤判排除）、產品正式寫法、技術數值、破折號、中英文空格
- 產出：`11_品檢\文稿檢查_<時間>\文稿檢查報告.html／.md`
- **必改 0 才往下**（有必改 exit 1）

## ④ 唸法清單＋逐字審稿（AI） ✅

1. **唸法清單**（程式）：
   ```powershell
   py 04_引擎\qa\read_check.py 11_品檢\文稿總審 1-1 1-2 …
   ```
   逐節列出每個英數詞、數字、多音詞、符號，以及「實際送給 TTS 的文字」。
   多音詞讀音：先用 OpenCC 轉簡體再查 pypinyin（詞組庫是簡體，繁體詞查不到會讀錯），`多音字清單.json` 的「詞」優先
2. **逐字審稿**（Claude 讀每一句）：檢查清單
   - 錯別字、漏字、贅字
   - 技術內容正確（數字、年份、協定、產品行為）
   - 用詞前後一致、專業寫法、台灣用語
   - 句子長度：字幕每頁 ≤16 字、≤9 字/秒，太長的句子拆開
   - 容易聽錯的說法（同音詞、連續專有名詞、數字串）
   - 物件文字與旁白一致
3. 產出 `11_品檢\文稿總審_<單元>\審稿報告.html／.md`：每一處「原文 → 建議 → 理由」

## ⑤ 使用者審稿 ⛔

- 使用者看審稿報告，決定改哪些 → 程式套用修改（先備份原稿到 `01_腳本\_修改前備份_<日期>\`）
- 套用後重跑 ③（必改 0）
- **文稿一次審完再配音**（改稿要重配、重渲，成本最高）

## ⑥ 選聲音 ⛔ ✅

```powershell
py 04_引擎\voice_preview.py --config 試音設定.json --out 11_品檢\聲音與語速\聲音試聽
```
- 寫幾段聲音描述（年齡、性別、口音、個性、粗細深沉）＋說話方式，用同一段約 20 秒的課文各唸一次
- 試聽頁：聲音內嵌、平均音高、語速、模型；聲音 id 記在 `voices.json`（重跑會沿用，不重複設計）
- 使用者選定 → 寫進 `00_規範\配音設定.json`（`voice_id`、`voice_description`、`style`、`_voice說明`）
- 注意：
  - 聲音存在**金鑰所屬的 Google 專案**，換 key 就要重新設計（只會相似）
  - 描述不要自相矛盾（「25 歲但像導師」「年輕有活力＋溫柔慢慢講」會被 Google 拒絕，HTTP 500）
  - 語速影響每集長度：語速 4.1 字/秒的聲音比 4.4 的長約 7%

## ⑦ 配音（Gemini Flash TTS） ✅

```powershell
py 04_引擎\tts_gemini.py 01_腳本\1-1_通訊協定與封包.md
```
- 模型 `auto`：每次查 Google，自動用**最新正式版 Flash TTS**（目前 gemini-3.8-flash-tts）
- 相鄰場景併成約 700 字一段送出（省請求數），用 faster-whisper 逐字時間＋difflib 對齊已知文稿，切回每場 mp3＋句級字幕
- 數字、IP、縮寫照 `發音規範.json` 轉；edge-tts 專用的權宜寫法（多音詞同音字、ping→聘）在 `skip_rules` 跳過
- 配額用完（429）會停，重跑同一指令從快取接續；短時間限制會自動等
- **整節成功才覆寫 `02_語音`**：先寫 `_staging`，全部完成＋對齊檢查通過才搬；原檔移到 `_上一版`；對齊可疑句 >10% 就停（聽過沒問題加 `--accept`）
- edge 權宜寫法（多音詞同音字、ping→聘、mail／GET／gov 逐字母、單獨 com→c o m、Mega→Megah）在 `skip_rules`，送 Gemini 時原文照送
- 備用：沒有金鑰時用 `tts.py`（edge-tts），輸出格式相同

## ⑧ 配音後聽檢 ✅

- 對齊檢查：配音時已做（每句長度合理才算對到）
- **AI 耳朵** `py 04_引擎\qa\ai_listen.py 11_品檢\聽檢 1-1 1-2 …`：每一場音檔＋文稿＋檢查清單（多音詞應唸、英數詞、數字）送最新 Gemini Flash（一般多模態模型）聽，逐項回報聽到的讀音與漏字多字；報告只列有疑問的場景、附音檔。任何聲音（Gemini、克隆、edge）都適用
- edge-tts 備用時另有 `qa\poly_ab.py`（同音字替換＋聲學比對）
- 只把「唸錯／不確定」做成試聽頁給使用者聽 ⛔；確認唸錯的寫進 `發音規範.json` 重配那一節

## ⑨ 建置（第一道品檢） ✅

```powershell
py 04_引擎\build_data.py 1-1
```
- 字幕：Netflix 繁中規範（每頁 ≤16 字、≤9 字/秒），無標點，網址顯示正式寫法
- 畫面文字：自動清標點與破折號、英數連字號不斷行、詞邊界斷行
- 物件同步：依旁白出現、唸完保留最後一項亮起；**文不對題直接擋下**（刻意不唸的寫 `allowStatic`）
- 不過就不產出

## ⑩ 版面探針（渲染前） ✅

```powershell
cd 04_引擎\remotion; node qa_layout.mjs ..\..\11_品檢\版面 1-1 1-2 …
```
- 瀏覽器實際量每段文字：超出畫面／安全區、重疊、間距、闖進字幕區、字級、對比（WCAG）、
  詞中斷行、物件標點、**文字貼邊（壓到圓角）**、版面偏移、畫面空白、標題過長
- **0 個問題才渲染**

## ⑪ 渲染 → 合併 ✅

```powershell
powershell -File render_v2.ps1 -Ver v8 -Ids 1-1,1-2,…      # 每節檢查 exit code 與檔案時間
py 04_引擎\assemble.py EP1 1-1 … 1-7 --ver v8             # 封面＋片頭＋過渡＋各節，響度 −16 LUFS
```
- **有一節失敗就停，不合併**（批次腳本已加）
- 渲染期間不要同時跑大量 API 請求（10/5 實測會搶網路，字型下載失敗）
- 新版本放 `v<n>` 資料夾，已交付的不覆寫

## ⑫ 品檢：逐節＋整集＋報告 ✅

```powershell
py 04_引擎\qa\qa_run.py v8_EP1 1-1 … --sec-dir 05_輸出_節/v8 --ep-dir 06_輸出_集/v8 --ep EP1=1-1,…
py 04_引擎\qa\final_qa.py 06_輸出_集\v8\EP1.mp4 --lufs -16 --minutes 28,33 --jump-skip 0-14.6
py 04_引擎\qa\make_report.py v8_EP1
```
- 字幕 C1～C7（標點、閃爍、抖動、字數語速、唸法殘留、字幕＝稿子）、同步 S1～S6、唸法 P、聲音 A、畫面 V、
  整集 E（長度 28～33 分、響度、接縫）、**畫面突跳 F11**（片頭業主影片排除）
- 報告一律 **HTML＋MD**；修改有前後對照圖
- 自我測試 `qa\selftest.py`：規則有改就跑，故意做壞的影片每一種都要被抓到

## ⑬ 交使用者抽檢 ⛔

- 先抽檢一集（改動大時），通過再做其他集
- 使用者回報「第幾分幾秒、看到什麼」→ 找根因 → 修程式／文稿 → **把這類問題加進品檢規則** → 重做
- 確認後刪中間版本（刪除前問使用者）

## ⑭ 收工紀錄 ✅

- `接手文件.md` 進度日誌：做了什麼、為什麼、踩到的坑、下一步（可直接照跑的指令）
- `工作清單.md` 勾選；進度面板（Claude Code 的 `/progress`）會自動讀它
