規則在 `00_規範\用詞規範.json`：網址寫成唸法、字母拆開寫、年份／百分比／編號用中文、協定名稱小寫、SLA 譯名、集數寫法、
大陸用語（樂詞網對照）、產品正式寫法、技術數值、破折號、中英文空格。**必改 0 才配音**（有必改時 exit 1）。
緣由：單元一的「mail點google點com」「百分之九十九點九」到成片才被抓到，必須重渲；文稿階段改只要幾秒。

## 一、流程：四道關卡

```
① 渲染前（build_data.py，不過就不產出資料檔）
   字幕覆蓋 >85%、單頁 <40 字、有項目的場景全部對上旁白
        │
② 渲染後・單節（qa_run.py ＋ qa_layout.mjs ＋ qa_asr.py）
   字幕／同步／唸法／版面／聲音／畫面 六類，逐節量測
        │
③ 合併後・整集（qa_run.py --ep）
   長度、響度、各節落差、接縫黑畫面與無聲
        │
④ 人工＋AI 看圖（make_report.py 產出的截圖總覽、修改前後對照）
   機器量不到的：畫面有沒有意義、教學重點是否一眼可辨
```

前三關全自動、量化、可重跑；第四關只看機器挑出來的地方，不必整支重看。

另有一道「⓪ 品檢自我測試」（`qa\selftest.py`）：品檢規則或門檻有改動時必跑。
把一支已知正常的影片故意做壞（黑畫面、無聲、音量、凍結、字幕閃爍、字幕抖動、標點、唸法殘留、
字幕不符、物件沒對旁白、講完又循環、超出畫面、標題過長），**每一種都要被抓到、正常版都要是 0**。
2026-10-04 首次執行就抓到品檢自己的 3 個錯（黑畫面門檻、S1 定義、測試比較），目前 13/13 有效。

## 二、檢查項目與門檻

### C 字幕（成片逐格量測字幕帶）

| 代號 | 檢查 | 門檻 | 怎麼量 |
|---|---|---|---|
| C1 | 句尾標點 | 0 | 讀字幕資料 |
| C1' | 句中標點 | 0（以全形空白斷開） | 讀字幕資料 |
| C2 | 換頁閃爍 | 0 | 成片：每次換頁前後 2 格內字幕帶不得有空白格 |
| C3 | 同頁抖動 | 位置變動 ≤2px | 成片：同一頁顯示期間，白字外框不得變動 |
| C4 | 單頁字數／語速／停留 | **≤16 字（必要時 18）、≤9 字/秒、5/6～7 秒** | 依 Netflix 繁體中文字幕規範；建置時 >18 字直接擋下 |
| C5 | 唸法文字殘留 | 0 | 字幕不得出現「D N S」「一九二點…」這類送進 TTS 的寫法 |
| C6 | 字幕與稿子一致 | 完全一致 | 去標點後逐字比對 |
| C7 | 斷句不佳 | 0 | 一頁不得以「的、了、」」等開頭；引號被拆到兩頁時，換頁處必須是引號內的標點 |

### S 物件與旁白同步

| 代號 | 檢查 | 門檻 |
|---|---|---|
| S1 | 有項目的場景（卡片、步驟、層、節點、膠囊、對照兩側）是否依旁白出場 | 100% |
| S2 | 項目唸完後是否又循環亮回前面 | 0 |
| S3 | cue 在旁白裡查不到 | 0（查不到就在分鏡補 cue） |
| S4 | 項目亮起比旁白唸到晚 | ≤1 秒 |
| S5 | 物件文字跟出場時旁白唸的句子對不上（文不對題） | **0，建置時直接擋下**（2026-10-04 起）：物件文字要用旁白裡的說法；刻意不逐項唸的場景在 plan 寫 `"allowStatic": true` 才放行。手寫 cue 指錯句子 → 自動改用物件文字重找 |
| S6 | 唸完之後的狀態 | 保留最後唸到的那一項亮起、其他維持淡，直到換場（不可退回「全部一樣亮」） |
| 逐項核對 | 每個物件出場秒數＋當下旁白正在唸的句子 | 報告列表，人工抽查 |

### P 唸法與寫法

| 代號 | 檢查 | 處理 |
|---|---|---|
| P1 | 旁白裡不在 `發音規範.json` 的英數詞（TTS 自己猜） | 每一個都要有規則，或明確標為「TTS 預設即正確」 |
| P2 | 回聽：把含英數詞的句子切出來做語音辨識 | 辨識結果找不到該詞的，報告附播放器人工試聽 |
| P3 | 同一詞多種寫法（HTTP／http、Port／port） | 統一寫法；網址、指令等原本就小寫的除外；全大寫的英文標籤是排版風格 |
| P4 | 多音詞（重送、轉圈、便宜…，清單在 `00_規範\多音字清單.json`） | 程式分不出聲調，每詞切 2 段給人試聽 |
| P5 | 英文單字唸得像不像（mail、GET、ping…） | `pron_check.english_check()`：3 種句子各合成一次，faster-whisper small 英文辨識，≥2/3 聽得出才算對；聲音唸不準又無法改寫的列入人工試聽 |

> 語音辨識（whisper）實測對英文縮寫、數字唸法分辨不出來（HTTP 21 次都沒聽出），只當試聽清單，不當判斷依據。

### L 版面（瀏覽器實際量測每段文字位置）

每個場景抽 3～6 格：進場完成、每次焦點切換後 0.6 秒、70% 處、淡出前。

| 檢查 | 門檻 |
|---|---|
| 超出畫面 | 0 |
| 超出安全區 | 左右 80px、上下 100px（ChatGPT 建議＝Remotion 官方 video-layout 規則） |
| 間距過小 | 相鄰兩段文字 ≥12px |
| 文字重疊 | 兩段文字交疊面積 ≤18% |
| 闖進字幕區 | 0 |
| 字級過小 | ≥24px（含 transform 縮放後） |
| 內容溢出 | 0 |
| 斷行不佳 | 最後一行不得只剩 1～3 個字 |
| 圖塊重疊 | 卡片、膠囊、圖片（有背景或框線、img、svg）彼此不得交疊 |
| 對比不足 | WCAG 2.x AA：一般文字 ≥4.5:1，大字（≥32px 或 ≥24px 粗體）≥3:1；底色取文字底下實際疊到的顏色；emoji 不量；淡化中的非焦點項不量 |
| 版面偏移 | 文字＋卡片外框的整體中心偏離畫面中線 ≤60px（本風格全部置中排版） |
| 詞中斷行 | 換行只能落在標點、空白或詞邊界（建置時用 jieba 插入的零寬空白）；行首不得是標點 |
| 畫面空白 | 場景開始 4 秒後畫面上必須有內容（標題或物件），不能只剩字幕與 LOGO |
| 標題過長 | ≥56px 的標題最多兩行 |
| 物件標點 | 畫面物件文字不得含「，」「；」、不得以「。」結尾（比照字幕規則；建置時自動把，；換成全形空白、刪行尾標點） |
| 文字貼邊 | 文字四角距離圓角框的弧線 ≥8px（膠囊形狀放兩行字時第二行會壓到半圓） |

### A 聲音・V 畫面

| 代號 | 檢查 | 門檻 |
|---|---|---|
| A1 | 響度 | 單節看一致性；整集 −16 LUFS ±1 |
| A2 | 真峰值 | ≤ −1.0 dBTP |
| A3 | 中段無聲 | 無 >1.5 秒（−45dB）的空白，片頭片尾除外 |
| A4 | 聲畫長度差 | ±0.1 秒 |
| V1 | 規格 | 1920×1080、30fps、H.264、AAC 48kHz 立體聲 |
| V2 | 黑畫面 | 無 >0.3 秒 |
| V3 | 最長靜止 | 參考值（2026-10-03 起不擋，見下） |
| V4 | 檔案新舊 | mp4 修改時間要晚於資料檔，否則是舊片 |
| V5 | 畫面突跳 | 內容區（不含字幕帶、上方標籤）單一格平均亮度差 >2.0 且前後格都小於它的 1/3 → 0 處 |

### E 整集

| 代號 | 檢查 | 門檻 |
|---|---|---|
| E1 | 長度 | 28～33 分 |
| E2 | 整集響度、各節落差 | −16 LUFS ±1；各節落差 ≤2 LU |
| E3 | 接縫 | 無黑畫面、無異常無聲（節與節之間的片尾測驗卡除外） |

| 規格 | 出處 |
|---|---|
| 字幕字數、語速、停留、標點 | Netflix Partner Help Center：Chinese (Traditional) Timed Text Style Guide；Timed Text Style Guide: General Requirements |
| 安全區 80／100px、字級 | Remotion 官方 agent skills（remotion-dev/skills）`video-layout.md`；ChatGPT 建議 |

## 五、2026-10-03／04 調整的規則

- **使用者抽檢 EP2 v5（2026-10-04 晚）**：①流程卡膠囊裡兩行說明靠左、壓到弧線 → 改大圓角矩形、文字置中，新增「文字貼邊」；
  ②物件文字兩行還留「，」→ 物件文字比照字幕規則，新增「物件標點」；③三項唸完後全部恢復一樣亮（像全滅）→ 唸完保留最後一項亮起（S6）；
  ④1-8 開頭膠囊文不對題、一開場整組出現 → S5 改成建置時擋下（同時修 1-1 S3、1-2 S3、1-4 S7、1-6 S5）。
  新規則驗證：用改前版本跑 1-14，抓到物件標點 85、文字貼邊 25（含使用者指出的「這個目的地是不是校內的」）。

- **字幕不放標點**：句尾標點刪除，句中斷句處改全形空白。
- **物件跟著旁白出場、唸完固定**：取消「畫面不得靜止超過 4 秒」的建置門檻與所有循環動畫
  （焦點輪播、光點循環、整塊沉降、循環光掃）。靜止比例改為參考值。
- **整集響度 −16 LUFS**：合併時兩段式 loudnorm。
- **字幕每頁 ≤16 字**（2026-10-04）：原本 24 字。標點處先切，沒有標點的長段用 jieba 斷詞找最靠近中間的詞邊界，英數詞不切開；時間依實際唸法長度分配；<5/6 秒的頁併入鄰頁。
- **字級**（2026-10-04）：卡片說明／膠囊／註解 30→38px、英文標籤 26→30px（ChatGPT 建議內文 ≥38px）。放不下時改版型，不縮字。
- **配色**（2026-10-04）：muted #8A8A8A→#9A9A9A；文字不再使用 faint #606060；章節編號改主色。全部為了達到 WCAG AA 對比。
- **換行與斷句**（2026-10-04 看圖發現）：畫面文字以短語換行（`Phrases.tsx`，在標點與「・」後切）；
  建置時用 jieba（繁簡通用大詞典＋`00_規範\專業詞庫.txt`）在詞與詞之間插入零寬空白，畫面套 `word-break: keep-all`、
  `line-break: strict`，中文只會在詞邊界換行。字幕切點避開虛詞開頭與引號中間。
- **畫面不空白**（2026-10-04）：物件改成唸到才出場後，左右對照與結語卡開頭會空好幾秒 →
  對照場景若第一邊超過 3 秒才出場，自動帶入稿子 VISUAL 行的標題；結語卡第一句一開場就出現；
  footer 找不到「項目之後」的旁白時改從頭找。
- **字幕語速以影格計算**：每頁 ≤9 字/秒以實際顯示的整數格檢查；整句語速貼著上限時向鄰頁借 1～2 格（≤0.3 秒）。
- **物件不突跳**（2026-10-04 使用者看 EP1 回報）：焦點亮暗、唸完全亮改成 0.4 秒漸變（`beats.ts narrate().weight`）；
  footer、結語句子、測驗說明一開始就佔好版面位置（透明），出現時只淡入，不再讓整塊內容往上跳；
  旁白沒唸到的物件整組一開場就出現；會轉的圖示（🌀⏳🔄⚙️）在旁白唸到「轉、載入、等待」那一項時真的轉。
  實測舊版 1-1 有 30 處單格突跳 → 新增 V5／F11 檢查。
- **英文唸法**（2026-10-04）：使用者決定維持全中文聲音；mail→M A I L、GET→G E T、gov→G O V、單獨的 com→c o m、Mega→Megah；
  ping、tracert、about 中文聲音唸不準，列入人工試聽。
