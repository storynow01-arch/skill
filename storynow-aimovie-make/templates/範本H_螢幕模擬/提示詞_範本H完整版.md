# 範本H 完整版提示詞（螢幕模擬 Screen Sim）

> **兩種用法**
> 1. **在這個 skill 裡**：說「範本H」，Claude 照 `README.md` 把文本寫成 `storyboard.json`（screen／phone 場景＋操作動作），用 `make_video.py --template H` 出片。下面的規則都已實作在 `engine/template/src/lib/screen.tsx`、`tpl/TemplateH.tsx` 與 `build.py`，不必再貼。
> 2. **在沒有這個 skill 的地方**（別台電腦、別的 AI）：把「提示詞本體」整段複製過去，只改【填寫區】。AI 會照規則重寫程式，風格與操作節奏會一致。
>
> **和原始需求的差別**：原始需求只說「給文本就產生像螢幕錄影的畫面」。這份把「像」拆成可以檢查的規則：真的介面長相、操作跟旁白對時的方式、鏡頭與泡泡的做法，以及 2026-10-01 失敗的教訓（空殼視窗、亂飄的假游標）。

## 提示詞本體（從這裡開始複製）

### 【填寫區】
- 主題：〔例：1-3 網域名稱與 DNS〕
- 內容：〔貼上文本或講義〕。找出要在螢幕上「做」的操作（打網址、跑指令、按按鈕、手機對話），其餘做成開場與重點整理；旁白一行一句
- 長度：約〔60〕秒（跟旁白走）
- 配音：〔台灣男聲，語速稍快〕
- 系統外觀：〔Windows 11〕

### 一、工作方式
1. 先給我看分鏡表（場景、每一步操作、旁白），我確認後才動手；正式配音前先給我看**每一步操作各一張截圖**的分鏡預覽
2. 用程式逐格渲染（例：Remotion），每一格畫面只由時間決定；**每個操作都寫一段「旁白原文」當定位點**，程式算出那段話被唸到的秒數，操作就在那一刻發生；找不到定位點就停下來，不要猜
3. 放大、標示、泡泡要**等前面的打字或指令輸出做完**才開始，不能指到還沒出現的東西
4. 規格：16:9、1920×1080、30 fps、H.264＋AAC；響度 −14 LUFS、峰值 −1.5 dBTP

### 二、整體風格（像真的螢幕錄影）
- 整個畫面就是一台 **Windows 11** 電腦：藍色漸層桌布、置中的工作列（開始、搜尋、檔案總管、Chrome、Edge、終端機；開著的程式下面有藍色小橫線）、右下角時間日期
- 字型用 Windows 原生字：介面 Segoe UI Variable＋微軟正黑體 UI；終端機 Cascadia Mono（在 Windows 上算圖）
- **Chrome**：灰藍分頁列＋白色作用中分頁（圓角上緣、載入中顯示藍色轉圈）、網址列（點下去變白底藍框、有閃爍游標）、左下角狀態泡泡（「正在解析主機...」「正在建立安全連線...」）
  內建頁面：新分頁（Google 字樣、搜尋框、捷徑）、Google 首頁、**無法連上這個網站（ERR_NAME_NOT_RESOLVED）**；其他網站用「標題、段落、按鈕、輸入框、卡片、清單、程式碼」區塊由上往下排
- **Windows 終端機**：深色標籤列「Windows PowerShell」、#0C0C0C 底、#CCCCCC 字、指令名稱淡黃色；開頭是真的 PowerShell 版權說明；指令輸出照中文版 Windows 的真實格式（例：nslookup 的「伺服器:」「未經授權的回答:」）
- **iPhone**：黑色圓角外框、動態島、訊息 App（上方 App 名稱、對方白泡泡、自己綠泡泡、下方輸入框＋麥克風）；淺灰藍背景
- 開場與重點整理：桌布上一張白色圓角卡片（像投影片視窗）
- 不要：空的模擬視窗、為了「有動態」在畫面上亂飄的游標、卡通風、霓虹風

### 三、操作與鏡頭
| 操作 | 畫面 |
|---|---|
| 點擊 | 游標（白底黑框箭頭）用 0.55 秒滑到目標，按下去縮小一點，冒出藍色漣漪；有滑鼠聲 |
| 打字 | 一個字一個字出現（每字 0.07～0.13 秒，像真人），每個字一聲鍵盤聲 |
| Enter | 瀏覽器：分頁轉圈、狀態泡泡依序顯示；終端機：輸出每 2 格印一行 |
| 載入完成 | 頁面淡入、分頁換成網站標題 |
| 打開終端機 | 游標點工作列圖示，視窗從 94% 放大淡入 |
| 放大 | 像 Screen Studio 的平滑推近（0.9 秒，緩入緩出），把目標放到畫面中間附近，不露出畫面外 |
| 標示 | 終端機：黃色螢光筆由左往右畫過那段文字；網頁：黃色圓角框 |
| 重點泡泡 | 白色圓角卡片＋陰影＋小尖角指著目標；粗體大字；重點詞黃色螢光筆由左往右畫；顯示到下一個泡泡或換鏡頭 |
| 手機 | 點擊＝半透明圓圈；訊息由下往上淡入；點麥克風變紅色並顯示「正在聆聽…」 |

### 四、字幕與聲音
- 字幕：底部置中黑底白字（不放標點，每頁 ≤16 字、≤9 字/秒），不壓到操作重點（手機往上放）
- 配樂：很輕的 lo-fi（音量約 0.25），旁白為主
- 音效：鍵盤、滑鼠、Enter（較重）、泡泡出現輕「啵」——時間跟畫面用同一份時間表

### 五、品檢
- 每個操作都對到旁白（cue 找不到就停）；泡泡文字要用旁白的說法；介面裡的字照真的寫（不要為了字級放大介面）
- 交付前用連續格確認：①像真的螢幕錄影 ②操作跟著旁白 ③推近＋泡泡＋螢光筆 ④游標滑過去才點、有聲音 ⑤沒有假動態
