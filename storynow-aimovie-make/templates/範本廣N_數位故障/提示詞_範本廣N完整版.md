# 提示詞：範本廣N 完整版（數位故障）

> 在沒有這個 skill 的地方，把下面整段（含程式規則）貼給 AI，再附上你的文本，就能做出同風格的影片。
> 有 skill 時不用貼：直接說「廣N」＋給文本，照 README 挑章、寫 storyboard，`make_ad.py` 一行出片。
> 出處：showreel 母提示詞「make a dynamic 60-second motion graphics video that shows what an incredible motion designer you are, like it's your showreel for a résumé. go all out.」延伸的「廣告 30 風格」第 1 批第 02 支（數位故障 Glitch，逐字見 `原始提示詞_02.txt`）；這份是把它落地成可重複的規格，並讓任何文本都能套用。

```
請把我附上的文本做成一支「數位故障」風格的短廣告（沒有旁白、沒有字幕），規格與規則如下，全部照做。

【要做的事】
故事裝置：一個被干擾的螢幕。資訊不是「出現」，而是「解碼成功」——每個字先跳亂碼，再一個字一個字在拍點鎖定；開場訊號中斷，最後訊號恢復。
先讀文本，從下面 7 種章裡挑 4～6 章（第一章一定是「開場」、最後一章一定是「收尾」，中間可任選、順序可換、同一種可以用兩次）：
1. 開場：紅色錯誤視窗「!! SIGNAL LOST」＋故障字 NO SIGNAL＋解碼進度條 → 英文縮寫（可省，最多 6 個英數）一拍一字解碼 → 名稱大字（約 10 字內）半拍一字鎖定 → 英文一行、全名或一句話＋綠色「SIGNAL ACQUIRED」。
2. 數字組合：1～3 個面板依序展開，每個是「數字＋單位＋0～6 行名單」，面板標題從 DECODING 變 [ OK ]；最後撕裂收走，合成一行大字（例：3 小時 30 名 4 個實作）＋下方一行。
3. 頻道切換：2～9 個同類項目像轉台，每台開頭雪花＋上捲＋切條；右上「CH01」頻道號與頻道格、TUNING... → PLAY；左邊色塊小標、名稱大字、英文一行、一句話、框線重點。
4. 錯誤修復：1～4 個亮點，每個先以紅色「!! ERROR · DATA CORRUPTED」視窗彈出、字是亂碼且一直撕裂，一拍後變綠「[OK] REPAIRED」、字一個個鎖定、進度條填滿；左邊 REPAIR LOG 一條條 [OK] 累積。
5. 數字鎖定：1～2 個大數字（吃角子老虎，一位一位在拍上停，每停一位色版爆一下），上方一行、下方一句＋「ADDR 0x… // LOCKED」；可加 1～2 張小數字卡。
6. 系統狀態：系統視窗由上往下展開，2～6 列「項目／說明／狀態框」逐列滑入，狀態框先轉圈再亮起；全部亮起後「ALL SYSTEMS ONLINE」＋一行。
7. 收尾：滿畫面雪花、色塊、撕裂、色版大錯開，6 拍內慢慢收斂成「英文小框＋名稱」、兩段標語（第二段綠色）、漸層線、一行小字、網址或電話；上方「SIGNAL RESTORED · 100%」。
先給我一張表（第幾章／章型／畫面上的字／預估秒數）讓我確認，確認後才寫程式。
數字只能用文本有的數字（可以數文本的項目，例：實作一～四 → 4 個實作），名稱、說明都要出自文本，不要編造。字放不下就改寫成名詞片語，不要縮小字。介面英文字（SIGNAL LOST、ERROR、REC、CH01…）是範本的螢幕介面，可以保留。

【風格】
深灰藍底 #1d1f2a（中央略亮的放射漸層）＋24 px 像素點格＋靜態掃描線＋一條慢慢往下移的淡藍亮帶；面板 #272b3c。
四色：螢光綠 #39ff88、洋紅 #ff2bd6、青 #22e4ff、紅 #ff3b5c；白 #f4f6ff、灰 #9aa0c4、墨 #141620。
中文 Noto Sans TC 700／900；介面字、數字、網址 Space Mono 400／700；故障大字 Rubik Glitch；頻道號 VT323。這三個英文字型沒有中文，字型串接時一律接 Noto Sans TC。
固定角標：四角 L 形框；左上「SEQ 02/05 · 章名」；左下紅點「REC · 一行英文」、右下一行小字，都靜止。畫面最下面 180 px 不放會快速變化的東西：雪花、十六進位資料流用遮罩在 y 800～880 淡出。
故障元件：RGB 三色版分離（洋紅、青、紅三層 screen 疊色、錯開）、橫向切條位移（內容切 10～22 條，各自橫移）、亂碼解碼（中文跳「訊號解碼錯誤資料損壞系統重啟傳輸頻道載入緩衝封包節點掃描同步」、英數跳 A–Z 0–9 #%&@$*?<>/=+，空白與中文標點不跳）、雪花（一張小雜訊紋理每格換位置）、資料損壞色塊（隨機長條，一半是點狀條紋）、背景十六進位資料流。
招牌轉場（每次換章，換章前 4 格～後 5 格）：畫面切成 20 條，每條各自橫移（大的到 420 px）、新舊兩章的切條隨機穿插（越接近換章點新章越多），整格套 RGB 分離濾鏡 30 px 爆開再收回，換章那 2 格整個畫面亂跳 40 px；偶爾幾條洋紅／青／綠色條。
其他：非轉場時 7% 的格停在前一格（跳格，最後 100 格不跳）；每小節第 3 拍有 2 格輕微撕裂（收尾章不做）。

【節奏與聲音】
phonk 110 BPM、A 小調（Am–F–C–G 每兩小節換），一拍 16.36 格，每一章從拍上開始、長度是整拍；字依讀字量（每秒 7 字，英數算半個字）決定停多久。
第一章只有長和弦墊底＋反拍 Hi-hat；第二章起：808 長音滑降（每小節第 1、8、11 個十六分音符）、第 3 拍拍手＋小鼓、十六分 Hi-hat＋隔小節 32 分滾奏、方波牛鈴旋律；最後兩小節回到墊底，1.4 秒淡出。
音效：開頭重擊；換章前一小節 riser、換章那拍重擊；收尾前兩小節 riser＋重擊；字鎖定短「嗶」、修復／上線雙音、轉台與錯誤彈出的數位雜訊、章內小重擊——全部對準時間表的事件。
母帶：開場墊底拉高約 12 dB（不然響度範圍超過 9 LU）、慢速音量騎乘、16 kHz 低通、拍手＋小鼓起音前 2～3 ms 短淡入並收一點高頻瞬間（避免 AAC 預回音突波）、4 倍超取樣真峰值正規化、前瞻限幅只壓最尖的約 1 dB；成品響度 −14 LUFS、真峰值 ≤ −2 dBTP。

【程式規則】
1. 先寫一份時間表（每一章第幾格開始、章內每個項目、每個字鎖定、每個數字停下的拍點、音效事件），畫面與配樂都只讀這份表。
2. 每一格的畫面只由「格數」算出來（不要 CSS transition、計時器、Math.random；亂數用固定種子，種子含格數才會每格不同）。
3. 數字一律用滾動（舊數字往上滑出、新數字從下滑入），不要逐格硬換。
4. 大面積閃光每秒最多 3 次；每格平均亮度 ≥ 10%；不要整片微幅呼吸縮放（要縮放就大方地推鏡）。
5. 版面依字數自動算：每個欄位有字級上下限，縮到下限還放不下就停下來告訴我哪個欄位太長、最多約幾字。
6. 中文字型只載入用到的字（含亂碼字池）；做完排一張「全字測試圖」（每種字型串接各排一次）確認沒有缺字。
7. 先出 12～20 張抽格總覽給我看（每章中段、每個換章點後 3 格、收尾），再整支算圖；1920×1080、30 fps。
```
