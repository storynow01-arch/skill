# 範本規格（每個範本上傳前都要符合）

> 2026-10-07 建立。範本會越來越多，這份規定「一個範本長什麼樣、要登記在哪裡」，並由 `check_templates.py` 自動檢查。
> **push 前一定要跑**：`python templates/check_templates.py`，全部 ✓ 才推（有 ✗ 時 exit 1）。檢查程式只讀不寫，不會改任何檔案。
> **自動擋下**：倉庫的 `.githooks/pre-push` 會在每次 push 前自動跑這個檢查，沒過就推不上去（不經過 Claude、手動 push 也擋）。
> 每台電腦啟用一次（在 skill 倉庫資料夾）：`git config core.hooksPath .githooks`。需要 Python＋ffprobe。
> 用 Claude 操作時會自動啟用（SKILL.md 硬規則：第一次 push 前檢查 `core.hooksPath`）；不用 Claude、手動 push 的人要自己執行上面那一行。

## 一、兩種範本

| 類型 | 說明 | 目前 |
|---|---|---|
| **共用引擎型** `shared` | 畫面元件放 `engine/template/src/tpl/Template<代號>.tsx`，一律用 `engine/scripts/make_video.py --template <代號>` 出片；文稿檢查、分鏡預覽、配音、聽檢、版面、最終品檢**全部共用**，共用工具升級時自動跟上 | A、B、C、D、H |
| **自帶產線型** `standalone` | 範本資料夾裡自帶 `engine/`（或專用產生器），有自己的流程；README 要寫清楚它用哪一套流程、哪些品質關卡 | E（15 步課程產線）、F、G、資訊科範本1 |

**新範本預設做成共用引擎型**（品質關卡最完整、維護最少）。只有像範本E 這種「整門課量產、有自己的步驟」才做自帶產線型。

**自帶產線型的流程受保護**：規格只要求 README 有固定段落與登記；**不要求、也不允許為了符合規格去改它的流程、引擎、規範**。
範本E 的 15 步與引擎由本機課程專案匯出（`export_template.py`），只能在本機專案改；skill 這邊只在 README 結尾附加「範本卡片」。

## 二、資料夾與必備檔案

```
templates/範本<代號>_<名稱>/          例：範本H_螢幕模擬（代號用下一個英文字母）
  README.md                            必備（固定段落見第三節）
  提示詞_範本<代號>完整版.md            必備：沒有這個 skill 時，整段複製就能做出同風格
  示範/示範.mp4                         必備：約 30 秒（25～35 秒）、1920×1080、有聲音；edge-tts；旁白介紹這個範本，畫面演出**每一種場景型別與招牌特效**（2026-10-07 使用者：10 秒太短）
  示範/poster.jpg                       必備：示範片封面（網站與 README 用）
  示範/總覽.jpg                         必備：示範片三格總覽
  示範/storyboard.json（或 示範分鏡*）  必備：示範片的分鏡，照著跑得出同一支示範片
  engine/                              自帶產線型才有
（`示範/` 只放上面這幾種檔案；備份、暫存放別處，檢查程式會擋——2026-10-07 範本E 的 10 秒版備份曾被匯出帶進 skill）
```
舊名「資訊科範本1」保留（已在網站與使用者口中使用），之後新範本一律用「範本<代號>_<名稱>」。

## 三、README 固定段落

開頭（標題下的引言）要有：`來源：`（哪來的、使用者怎麼評價）、`觸發：`（使用者說什麼會用到這個範本）。
接著依序有這些 `##` 段落（標題文字開頭要一樣，後面可加說明）：

| 段落 | 內容 |
|---|---|
| `## 長什麼樣` 或 `## 30 秒示範片` | 示範片封面＋連結、總覽圖、示範分鏡與完整版提示詞的連結 |
| `## 適合` | 適合什麼內容、不適合什麼（網站卡片直接讀這段） |
| `## 原始提示詞` | 逐字保存使用者給的提示詞或需求（另存成 .txt 也可以，但這段要放連結） |
| `## 流程與品檢` | 用哪一套流程（十二步／範本流程／自帶的 N 步），有哪些品質關卡 |
| `## 概念忠實度檢查` | 招牌特徵表（`| # | 招牌特徵 | 怎麼驗 | 現況 |`）——make_video 出片後會把它印出來要人核對 |
| `## 範本設定` | Composition／引擎、配樂、旁白、字幕、音效、切點 |

README 裡的相對連結都要連得到（檢查程式會驗）。

## 四、要登記的地方（漏一個就會「網站看不到」「Claude 不知道有這個範本」）

| 地方 | 要做什麼 | 檢查 |
|---|---|---|
| `templates/範本清單.json` | 加一筆：代號、資料夾、類型、名稱、觸發用語 | ✓ 自動 |
| `SKILL.md` 快速指令表 | 加一列：觸發用語 → 照 README 做什麼 | ✓ 自動（找資料夾名） |
| `SKILL.md` 工具與檔案 | 加一行說明資料夾內容 | ✓ 自動 |
| `site/build.mjs` 的 `TEMPLATES` | 加 `['範本<代號>_', '<小寫代號>']`（網站卡片） | ✓ 自動 |
| 根目錄 `README.md` | 加一行範本介紹 | ✓ 自動（找代號） |
| 共用引擎型：`engine/scripts/make_video.py` 的 `TPL`、`engine/template/src/Root.tsx` 的 Composition | 加代號與 `Template<代號>` | ✓ 自動 |
| 共用引擎型：`templates/範本風格_場景語彙.md` | 場景型別跟 A～D 不同時，加一節說明 | ✓ 自動 |

## 五、新增範本 SOP（照順序做）

1. 試作（不在 skill 裡）：先做 20～30 秒試作給使用者看，使用者說「做成範本」才開始
2. 決定類型（預設共用引擎型）與代號；在 `範本清單.json` 登記
3. 寫程式（共用引擎型：`tpl/Template<代號>.tsx`＋需要的 `lib/` 元件；build.py 只能「加」不能改既有行為）
4. 寫範例分鏡，跑 `make_video.py --template <代號> --preview` → **分鏡預覽給使用者看** ⛔
5. 正式出片 → `final_qa/final_qa.py` **全部通過**（不過就修，不放寬門檻）→ 連續格核對概念忠實度
6. 做示範片（約 30 秒、edge-tts、演出所有場景型別與招牌特效、最終品檢全過）、poster、總覽
7. 寫 README（第三節段落）、完整版提示詞
8. 登記第四節的每個地方
9. `python templates/check_templates.py` 全部 ✓ → `node site/build.mjs` 看卡片 → push → 確認 Vercel 部署成功

## 六、改既有範本時

- 共用程式（build.py、final_qa、term_check、make_video）只能**加**不能改既有行為；改了要讓其他範本的示範片重跑一次確認沒壞
- 範本E：只在本機課程專案改，再 `export_template.py` 匯出；不要直接改 skill 裡的範本E（會被下次匯出蓋掉）
- 改完一樣跑 `check_templates.py`

## 網路儀表板（2026-10-09）
網路儀表板（storynow-video-workflow.vercel.app，`site/build.mjs`）和本機展示網頁同一套外觀（樣式直接讀 `reel-showcase/assets/展示網頁樣式/site.css`），五區：範本／廣告／工作流與工具／科目包／作品集。
- **範本 vs 廣告**：`範本清單.json` 每一筆可加 `"kind": "ad"`＝沒有旁白的廣告範本（出現在「廣告」區）；不寫＝有旁白（「範本」區）。從本機 REEL「純廣告」收進 skill 時一定要加。
- 卡片封面＝`示範/poster.jpg`、預覽與單支頁播放＝`示範/示範.mp4`（30 秒左右），兩個都要進倉庫。
- **作品集**：本機跑 `python site/sync_works.py <頻道資料夾>` 更新 `site/作品集.json`＋`site/works/` 封面，commit＋push 才會上網（網站只讀遠端倉庫；影片不上傳）。
