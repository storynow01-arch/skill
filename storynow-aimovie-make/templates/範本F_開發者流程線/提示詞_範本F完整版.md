# 範本F 完整版提示詞（01 風格：開發者流程線）

> **兩種用法**
> 1. **在這個 skill 裡**：說「範本F」，Claude 會照 `README.md` 把文本寫成 `storyboard.json`，用 `engine/make.py` 出片。畫面元件已寫死在 `engine/lib_F.js`，下面的規則都已經實作，不必再貼。
> 2. **在沒有這個 skill 的地方**（別台電腦、別的 AI）：把下面「提示詞本體」整段複製過去，只改【填寫區】。AI 會照規則重寫程式，風格會很接近，但細節不會跟引擎版一模一樣。

## 提示詞本體（從這裡開始複製）

### 【填寫區】
- 主題：〔例：介紹本校資訊科的專題製作流程〕
- 內容來源：〔貼上文本，或給網址〕。請上網搜尋跟研究，把每一步實際「產出什麼、改變什麼」找出來
- 流程步驟（3～6 步，依序）：〔例：選題 → 寫企劃 → 分工 → 實作 → 發表〕
- 長度：約〔30〕秒（實際長度跟旁白走，最多超過 15%）
- 配音：〔溫暖的台灣男生〕
- 片尾署名：由〔姓名〕製作
- 資料來源小字：〔網址〕

### 一、工作方式
1. 先研究內容，再給我看 rundown 和分鏡表（秒數、旁白、畫面），我確認後才開始動手
2. 確認後一路做到成片，中途不用再問我；只有缺少關鍵資料時才停下來
3. 用程式逐格渲染：HTML Canvas 的 seek(t) ＋ Playwright 截圖 ＋ ffmpeg。每一格畫面只由時間 t 決定，不用計時器和亂數
4. 規格：16:9、1920×1080、30 fps、H.264（CRF 16）＋ AAC

### 二、整體風格（深色開發者風格）
- 背景近黑 #0b0e14，48px 間距的點陣（半徑 1.6px、白色 5% 透明），頂部中央一團淡藍光暈（#5AA9FF、10% 透明、半徑約 1100px）
- 面板底色 #131924，細框線 #263043，圓角 20px
- 文字象牙白 #EDEAE3，次要文字灰 #7C8698
- 每一步各有一個代表色，依序：琥珀 #FFB547、藍 #5AA9FF、紫 #B38CFF、綠 #3DDC97、紅 #FF6B6B（超過 5 步就循環）
- 中文字型：微軟正黑體（粗體）；指令、檔名、標語、數字用等寬字：Cascadia Code／Consolas
- 不要：漸層大標題、米白底、斜體標題、圓角膠囊按鈕當裝飾、emoji 當主視覺

### 三、場景結構（每一段旁白一個場景）
| 場景 | 旁白功能 | 畫面 |
|---|---|---|
| 1 開場鉤子 | 點出問題 | macOS 風格終端機視窗（左上紅黃綠三圓點）。程式碼一行行往上捲動，最後幾行變紅色表示出錯；念到「但……」時，右側用 outBack 彈出一個黃色大圓章，裡面是問號 |
| 2 總覽 | 說出主題與步驟數 | 中央大標題（英文用 Segoe UI 粗體，中文用正黑體），下面一行灰色副標；上方出現流程節點列（見第四節），節點以 0.08 秒間隔依序彈出，此時全部是灰色 |
| 3～N 每一步 | 每段講一步 | 上方點亮該步節點；下方舞台依這一步的性質，從「第五節 舞台畫面庫」選一種畫面 |
| 最後 | 總結＋署名 | 五個節點之間的連線全部點亮；中央用等寬字大標語「起點 → 終點」（左詞琥珀色、右詞綠色、中間灰色箭頭），outBack 彈出；下面一行白字總結；再下面是白色細框膠囊「由 ○○ 製作」；右下角 22px 灰色資料來源小字 |

### 三之一、兩段式（一部影片介紹兩件事時）
- 兩部分各有自己的一組節點列；第二部分開頭放一個轉場段：舊節點列往上飄 80px 淡出，新節點列以 0.08 秒間隔彈出（灰色），中央大標題＋灰色副標
- 第一部分的收尾用標語（例：「想法 → 工具」），第二部分的收尾才放署名

### 四、流程節點列（從場景 2 到片尾常駐）
- 位置：畫面上方 y = 230，步驟平均橫排（5 步時 x = 300、630、960、1290、1620）
- 每個節點：半徑 44px 的圓，中間放等寬數字；節點下方 +92px 放指令或步驟名稱（等寬字 28px），+132px 放中文說明（26px）
- 未點亮：面板底色＋灰框、灰字
- 點亮：講到哪一步，該節點在 0.35 秒內變成代表色；目前這一步外圈有半徑 70px 的同色光暈，透明度以 0.35 ± 0.15 呼吸（每秒約 0.8 次）
- 節點間的連線是 4px 灰線；下一步點亮前 0.4 秒，白色亮線由左往右延伸過去

### 五、舞台畫面庫（畫面放在 y 420～880 之間，依步驟性質選用）
| 步驟性質 | 畫面 |
|---|---|
| 提問、釐清、訪談 | Q/A 對話氣泡依序滑入（間隔 0.55 秒）：問題用琥珀色框＋等寬「Q」，回答用灰框＋「A」並往右縮排 90px。講到「整理、定義」時，右邊彈出文件卡（檔名用等寬字，例：GLOSSARY.md），條列項目每 0.1 秒滑入一條 |
| 整理、彙整、寫成文件 | 上一步的多個元素縮小、移向中央並淡出（0.8 秒）；接著一張文件卡從中央彈出：標題列用等寬字（例：SPEC #42 主題），下面 3 條重點，每 0.25 秒出現一條，條首放小方塊 |
| 拆解、分工 | 上一張大卡縮小淡出（0.3 秒），同時 4 張小卡以 0.08 秒間隔彈出排成一列（每張左上等寬編號 T1～T4、中間名稱）；講到「相依、順序」時，卡片下方用紫色虛線弧線依序（間隔 0.12 秒）描出相依關係，最下方一行灰字說明「虛線 = 被誰卡住」 |
| 執行、實作、測試 | 上方一個狀態膠囊，先顯示紅色「failed」（紅點＋等寬字），講到關鍵詞 0.6 秒後翻成綠色「passed」；下方任務卡從左到右每 0.3 秒打勾一張，邊框同時變綠 |
| 檢查、審核、驗收 | 2～3 條寬版檢查列（粗體等寬標題＋灰色說明），講到哪一項，右側綠色圓點裡的勾勾就分兩筆畫出（0.45 秒），外框變綠；最下方一行灰色小字總結 |
| 成果數據（人數、獎牌數） | 上方狀態膠囊從前一個狀態翻成更好的狀態（例：「分區賽 雙冠」→「全國賽 銅牌」）；下方 3 張數字卡，數字從 0 跑到目標值（1.2 秒，快進慢停），單位小字、說明灰字 |
| 關鍵數字＋名單 | 1～2 個大數字（等寬字 120px，第一個綠、第二個琥珀），數字從 0 跑，**在旁白念到該數字時剛好停住**；下方名單膠囊（學校、單位）每 0.1 秒滑入一顆 |
| 上線、部署 | 狀態膠囊紅色「deploying …」翻成綠色「live ✓」；下方網址卡（等寬字）＋QR 方塊，念到「掃」時打勾 |
| 三步串接 | 三張卡 A → B → C 用箭頭連起，依序打勾；上方狀態膠囊翻成「已完成」 |
| 其他 | 用一個能看懂的具體物件表示這一步的產出（檔案、清單、按鈕、圖表），不要只放文字方塊 |

畫面裡的文字（問答內容、檔名、任務名稱、檢查項目）一律從研究到的真實內容取，不要編造。

### 六、動態規則
- 主角元素用 outBack 彈出：從 0.65 倍放大到 1 倍，略超過再回彈，0.5 秒；透明度在前 45% 時間內就到 1
- 次要元素用 outExpo 快進慢停：從下方 40px 上滑並淡入，0.55 秒
- 同一組元素分批進場，彼此只差 0.05～0.1 秒，不要一個等一個
- 畫面跟旁白同步：元素在旁白念到該詞時出現，時間＝關鍵詞在句中的字元位置 ÷ 句長 × 該句秒數；如果念到的時間太晚、畫面會空太久，就把主體提前到該段開始後 0.15～0.5 秒，細節再跟著關鍵詞出現
- 場景轉場：下一段開始前 0.2 秒，舞台內容往上飄 80px 並在 0.4 秒內淡出，新內容同時進場，不留空白；流程節點列不參與轉場
- 片尾最後 0.7 秒整個畫面淡出到背景色

### 七、字幕
- 畫面最下方：深色膠囊（rgba(5,7,12,.85)），高 74px、上緣 y = 962，象牙白字 42px
- 按標點切成小句，同一時間只顯示一句，每句 0.1 秒淡入淡出
- 字幕用原稿（英文指令照寫，例：grill-with-docs）；畫面內容不得進入 y > 940 的字幕區

### 八、配音與配樂
- 配音：專案有 Gemini API 金鑰就用 Gemini Flash TTS，否則 edge-tts（zh-TW-YunJheNeural，語速 +8%）；每段旁白分開生成，段與段之間停 0.18 秒，片頭留 0.4 秒、片尾留 1.8 秒
- 另存一份配音稿：英文指令的連字號改成空格（grill-with-docs → grill with docs），數字改成中文念法；字幕仍用原稿
- 配樂用程式合成，96 BPM，輕柔電子：和弦 Fmaj7 → Am7 → Dm7 → B♭maj7，每兩小節換一次；柔和長音墊底＋電鋼琴分解和弦；第二小節起加輕 kick（第 1、3 拍）和反拍 hi-hat；片尾最後 4 秒長音收尾，最後 1.5 秒淡出
- 每個節點點亮時加一聲短提示音（逐步升高：C5、D5、E5、G5、A5）；署名出現時兩聲高音
- 人聲閃避：用旁白音量包絡（0.25 秒平均）把音樂最多壓低 70%，音樂峰值約為旁白的三分之一
- 混音後 loudnorm（I = -15、TP = -2）再加限幅，峰值不超過 -1.5 dBFS

### 九、品質檢查（渲染整支之前）
- 抽每段的開頭、中段，以及每個轉場前後 0.2 秒的畫面，拼成縮圖總覽檢查：
  - 文字落單斷行、文字超出面板
  - 元素互相重疊、壓到節點列或字幕區
  - 轉場時畫面空白超過 0.2 秒
  - 某一段舞台超過 1 秒是空的
- 有問題先修再抽一次，全部沒問題才整支渲染，最後合成聲音並量響度

### 十、交付
- 成品 MP4，以及 scene.html、render.mjs、build_audio.py、make_music.py、timings.js、旁白稿（字幕版、配音版）、rundown 分鏡表，放在同一個資料夾
- 用不到的檔案移到 To_delete/，不要直接刪
- 完成時告訴我：實際長度、和確認版不同的地方、響度量測結果

## 附註（不用複製）
- 這份範本把 01 影片裡原本「沒寫出來、由 AI 自己決定」的部分都寫成規則了：配色、節點列、舞台畫面庫、音樂。也併入了 06 提示詞的動態規則（outBack、錯開、念到才出現、上飄轉場、字幕）。

- 步驟最好 3～6 步。超過 6 步，節點會太擠，建議分成兩支影片。
